Enunciado

El profe dejó un ejercicio de laboratorio: en Oracle SQL Developer había que escribir tres tablas con temática de fútbol (jugador, liga y equipo), con sus atributos y relacionadas entre sí, y después plantear tres expresiones de álgebra relacional sobre ellas.

En clase no alcanzamos a hacerlo, así que lo resolví después y lo agregué acá como práctica complementaria.

2

Modelo relacional

La idea es simple: una liga tiene muchos equipos y un equipo tiene muchos jugadores. Las dos son relaciones uno a muchos y las resolví con llaves foráneas: equipo.id_liga apunta a liga y jugador.id_equipo apunta a equipo.

A cada tabla le puse llave primaria, NOT NULL en lo obligatorio, UNIQUE donde tenía sentido (el nombre de la liga, el nombre del equipo y el dorsal dentro de un equipo) y algunos CHECK: que la posición sea una de las válidas, que el dorsal esté entre 1 y 99 y que los goles no sean negativos.

TablaAtributos
LIGAid_liga (PK), nombre (único), pais, anio_fundacion
EQUIPOid_equipo (PK), nombre (único), ciudad, estadio, anio_fundacion, id_liga (FK → LIGA)
JUGADORid_jugador (PK), nombre, apellido, fecha_nacimiento, nacionalidad, posicion, dorsal, goles, id_equipo (FK → EQUIPO)
3

Script de creación de tablas

Este es el script para Oracle SQL Developer. El archivo completo, con los datos de ejemplo y las tres consultas, se puede descargar arriba.

CREATE TABLE liga (
    id_liga          NUMBER(3)      NOT NULL,
    nombre           VARCHAR2(60)   NOT NULL,
    pais             VARCHAR2(40)   NOT NULL,
    anio_fundacion   NUMBER(4)      NOT NULL,
    CONSTRAINT pk_liga        PRIMARY KEY (id_liga),
    CONSTRAINT uq_liga_nombre UNIQUE (nombre),
    CONSTRAINT ck_liga_anio   CHECK (anio_fundacion BETWEEN 1850 AND 2100)
);

CREATE TABLE equipo (
    id_equipo        NUMBER(4)      NOT NULL,
    nombre           VARCHAR2(60)   NOT NULL,
    ciudad           VARCHAR2(40)   NOT NULL,
    estadio          VARCHAR2(60),
    anio_fundacion   NUMBER(4)      NOT NULL,
    id_liga          NUMBER(3)      NOT NULL,
    CONSTRAINT pk_equipo      PRIMARY KEY (id_equipo),
    CONSTRAINT uq_equipo_nom  UNIQUE (nombre),
    CONSTRAINT fk_equipo_liga FOREIGN KEY (id_liga) REFERENCES liga (id_liga),
    CONSTRAINT ck_equipo_anio CHECK (anio_fundacion BETWEEN 1850 AND 2100)
);

CREATE TABLE jugador (
    id_jugador        NUMBER(6)      NOT NULL,
    nombre            VARCHAR2(50)   NOT NULL,
    apellido          VARCHAR2(50)   NOT NULL,
    fecha_nacimiento  DATE           NOT NULL,
    nacionalidad      VARCHAR2(40)   NOT NULL,
    posicion          VARCHAR2(15)   NOT NULL,
    dorsal            NUMBER(2)      NOT NULL,
    goles             NUMBER(4)      DEFAULT 0 NOT NULL,
    id_equipo         NUMBER(4)      NOT NULL,
    CONSTRAINT pk_jugador        PRIMARY KEY (id_jugador),
    CONSTRAINT fk_jugador_equipo FOREIGN KEY (id_equipo) REFERENCES equipo (id_equipo),
    CONSTRAINT uq_jugador_dorsal UNIQUE (id_equipo, dorsal),
    CONSTRAINT ck_jugador_pos    CHECK (posicion IN ('Portero','Defensa','Mediocampista','Delantero')),
    CONSTRAINT ck_jugador_dorsal CHECK (dorsal BETWEEN 1 AND 99),
    CONSTRAINT ck_jugador_goles  CHECK (goles >= 0)
);

Tres expresiones de álgebra relacional

Cada expresión va en álgebra relacional, con su consulta equivalente en SQL y lo que devuelve con los datos de ejemplo. Los símbolos: σ es selección, π proyección, × producto cartesiano, ρ renombrar, ⋈ reunión y − diferencia.

Expresión 1 — Selección y proyección

Se pide: Nombre, apellido y goles de los delanteros colombianos con 10 o más goles.

Álgebra relacional

π nombre, apellido, goles (
    σ posicion = 'Delantero' ∧ nacionalidad = 'Colombia' ∧ goles ≥ 10 ( JUGADOR )
)

Solo se usa una tabla: la selección se queda con las filas que cumplen las tres condiciones y la proyección deja nada más las tres columnas que piden.

Equivalente en SQL (Oracle)

SELECT nombre, apellido, goles
FROM   jugador
WHERE  posicion = 'Delantero'
  AND  nacionalidad = 'Colombia'
  AND  goles >= 10;

Expresión 2 — Reunión de las tres tablas

Se pide: Apellido del jugador, nombre de su equipo y nombre de la liga, solo para la Liga BetPlay.

Álgebra relacional

π J.apellido, E.nombre, L.nombre (
    σ J.id_equipo = E.id_equipo ∧ E.id_liga = L.id_liga ∧ L.nombre = 'Liga BetPlay'
      ( ρJ(JUGADOR) × ρE(EQUIPO) × ρL(LIGA) )
)

Está en la notación de clase: producto cartesiano más selección. Las igualdades de llave dentro de la selección hacen el trabajo de la reunión (⋈); da lo mismo que JUGADOR ⋈ EQUIPO ⋈ LIGA con la liga filtrada.

Equivalente en SQL (Oracle)

SELECT j.apellido, e.nombre AS equipo, l.nombre AS liga
FROM   jugador j, equipo e, liga l
WHERE  j.id_equipo = e.id_equipo
  AND  e.id_liga   = l.id_liga
  AND  l.nombre    = 'Liga BetPlay';

Expresión 3 — Diferencia de conjuntos

Se pide: Equipos que no tienen ningún jugador registrado.

Álgebra relacional

π nombre, ciudad (
    EQUIPO ⋈ ( π id_equipo (EQUIPO)  −  π id_equipo (JUGADOR) )
)

La resta deja los id_equipo que están en EQUIPO pero no aparecen nunca en JUGADOR, y la reunión me trae el nombre y la ciudad de esos equipos. En Oracle la resta se escribe MINUS.

Equivalente en SQL (Oracle)

SELECT nombre, ciudad
FROM   equipo
WHERE  id_equipo IN (SELECT id_equipo FROM equipo
                     MINUS
                     SELECT id_equipo FROM jugador);

Resultado con los datos de ejemplo (1 fila)

nombreciudad
Deportivo Nuevo FCBogotá
